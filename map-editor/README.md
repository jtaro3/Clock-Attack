# 独立マップエディター

## 起動・画像追加

1. 地面として塗るPNGは maps/tiles、岩・丸太など個別に置くPNGは maps/object に入れます。どちらも縦横32pxの倍数にします。
2. open-editor.cmd を実行します。画像一覧を再生成してエディターを開きます。
3. パレットが「地面チップ」と「オブジェクト」に分かれます。地面チップは塗り、オブジェクトはマップ上をタップして配置します。複数マスの大きさはファイル名の後ろに表示します。

index.htmlの直接起動では、前回生成した一覧を使います。画像の追加・削除・変更後はopen-editor.cmdを実行してください。HTTPサーバーは不要です。PNG形式や32pxの倍数でないサイズなら一覧の更新を止め、ファイル名をエラー表示します。

このフォルダ全体をコピーすれば別の場所でも使えます。

## パレットの表示仕様

- ファイル名をそのまま表示します。翻訳や名称の置き換えはしません。
- 地面チップを先に、オブジェクトを後に並べます。オブジェクトのカードは青紫系の背景色で区別します。
- 各分類内はファイル名の昇順です。ただし、既存の地面チップ4枚は先頭に grass.png → grass-dark.png → flowers.png → soil.png の順で表示します。
- 並び替えは文字列として行います。数字部分を数値として並べる方式ではないため、連番は 01、02、03 のように桁数を揃えると意図した順序になります。
- 1マスは32×32pxです。画像の横幅・高さをそれぞれ32で割り、複数マスの画像にはファイル名の後ろへ「(横マス数×縦マス数)」を付けます。64×32pxなら (2×1)、32×64pxなら (1×2)、64×64pxなら (2×2) です。
- 32×32pxの画像には (1×1) を付けません。この補足表示はエディターが生成するもので、画像ファイル名は変更しません。
- オブジェクトのプレビューは縦横比を保ってカード内に収めます。配置時は元画像のマス数を使います。

## 保存とゲームへの反映

「保存」はブラウザー内の保存です。「書き出し」でclock-attack-grassland.jsonを出力し、ゲームのmaps内の同名JSONを置き換えます。JSONは画像を含むため、追加チップの画像をゲームへ別途コピーする必要はありません。バランス調整用game-data.jsonには上書きしないでください。
公開時はdist/mapsにも同じJSONをコピーし、公開作業が必要です。

画像はファイル名で対応付けます。tilesとobjectの間で画像を移動しても、名前が同じなら保存済みマップの参照は維持されます。両フォルダ間で同じファイル名は使えません。使用中の画像を削除・改名すると読み込めなくなるため、書き出したJSONをバックアップしてください。旧4種類だけのマップJSONも読み込めます。

## 描画ツール

1・3・5・7マスを選べます。クリック位置を中央に直線状に塗ります。選択中の3・5・7マスを再度押すと横→縦→右下がり斜め→右上がり斜めの順で回転します。マップ外は塗りません。オブジェクト消しゴムで配置済みオブジェクトをタップすると削除できます。地面チップは残ります。

3×3・10×10マスの四角形ツールも使えます。マップの端では、マップ内のマスだけを塗ります。オブジェクトはブラシの大きさに関係なく、クリックしたマスを左上として1個ずつ配置します。配置済みオブジェクトとの重なりや、マップ外にはみ出す配置はできません。消しゴムではオブジェクトが占めるどのマスを押しても、そのオブジェクト全体を削除します。

## 台帳との関係

パレットの画像一覧は画像フォルダから作ります。map_tilesのasset_keyから、assetsの同じキーのsprite_fileへ対応付け、categoryをカードの補足ラベル、palette_colorをカード背景色に反映します。色は #C6D6BC のように6桁のカラーコードで指定します。空欄や未登録画像には既定表示を使います。

更新手順は、main.odsで編集 → CSV出力ボタンで検証済みgame-data.json生成 → open-editor.cmdで起動、です。CSV検証では有効行のキー重複、assetsへの参照、カラーコードを検査し、エラーがあればJSON生成を止めます。open-editor.cmdは親フォルダのgame-data.jsonを読み、表示設定をtile-catalog.jsに取り込みます。独立フォルダとしてコピーした場合は、最後に生成したカタログで表示できます。親フォルダにJSONがない場合、一覧を再生成すると既定表示になります。

map_tilesのenabled=0の行は設定をJSONに出力しません。画像フォルダにある未登録画像もパレットには表示するため、enabledで画像一覧を非表示にする機能はありません。maps/object 内の画像は32×32pxでもオブジェクト層に配置します。従来との互換性のため、maps/tiles 内でも32pxを超える画像はオブジェクトとして扱います。

## 通行判定とプレイヤーの見え方

walkable=1は通行可能、0は通行不可です。collision_lengthは縦、collision_widthは横のマス数で、1マス=32pxです。判定範囲は配置位置の左上から指定した縦横の長方形です。通行不可の場合は両方に0より大きい値が必要です。値はJSONと画像カタログへ取り込まれ、ゲームではプレイヤーの足元と敵が範囲を通り抜けないようにします。破壊可否・耐久力はまだ未実装です。マップを書き出してゲーム側のmapsへ置くと、配置したオブジェクトに判定が付きます。

「プレイヤー配置」を押してからマップをクリックすると、ゲームと同じ画像・表示サイズの確認用プレイヤーを置けます。別のマスをクリックすると置き直せます。通行不可の範囲は赤枠で表示し、足元が重なる場合はメッセージを表示します。同じボタンをもう一度押すとプレイヤーを非表示にします。この位置はゲームの開始位置として保存・書き出しません。マスターのplayer_scaleはエディター起動時に取り込みます。
